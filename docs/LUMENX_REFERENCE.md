# LumenX Studio 参考与改进说明

参考项目：Alibaba LumenX Studio

项目地址：<https://github.com/alibaba/lumenx>

许可证：MIT License

本项目参考了 LumenX Studio 在内容分析、故事资产提取和分阶段生成方面的产品思路。在此基础上，我们围绕“多章节小说转可编辑 YAML 剧本”重新设计并实现了一套 Java 工作流，重点解决长文本一致性、剧本结构可靠性和作者后续编辑问题。

## 我们的改进

### 1. 从单次生成改为全书规划与逐章精编

系统先读取三章以上的完整小说，建立覆盖全书的改编蓝图，再以共享的 Story Bible 和蓝图为约束并行生成各章剧本。每章都记录进入状态、退出状态、必须保留的动作和对白，减少跨章节重复、人物状态跳变和关键情节遗漏。

### 2. 从等待最终结果改为渐进式可见

Story Bible 完成后立即展示人物、地点和道具；每完成一个章节，场景、动作和对白就追加到页面；全部内容通过校验后再开放 YAML、结构编辑和下载。作者可以在生成过程中持续看到有效结果，而不必等待整本处理结束。

### 3. 增加模型响应归一化与自动修复

模型输出不会直接进入最终对象。Java 层会统一处理字符串与对象混用、字段别名、错误容器、缺失数组、无效引用和不规范 ID；JSON 解析失败时会请求一次结构修复。由此解决了 `project`、`continuity`、`adaptationNotes` 等字段因模型输出不稳定而导致的反序列化失败。

### 4. 建立可交付、可验证的 YAML 剧本 Schema

项目定义了完整的 YAML Schema 和 JSON Schema，覆盖项目元数据、Story Bible、场景、动作与对白 Beat、媒介结构、连续性、原文依据和改编说明。除字段类型校验外，Java 还检查人物、道具、对白说话人和前后场景的跨对象引用。

### 5. 将剧本形式落实到每个场景

电影、电视剧、竖屏短剧和舞台剧不只是项目标签，而是拥有不同的场景结构：

- 电影：三幕推进、视觉动作、空间关系、镜头和声音设计。
- 电视剧：`TEASER/ACT/TAG`、A/B/C 故事线和幕尾转折。
- 竖屏短剧：`HOOK/ESCALATION/REVERSAL/CLIFFHANGER` 与秒级节奏。
- 舞台剧：幕/场、演员出入场、站位、灯光、音效和换景提示。

每个场景通过 `formatDesign` 保存幕段、故事线、戏剧功能、预计时长和制作提示，使生成结果具有明确的媒介差异。

### 6. 增加原文可追溯能力

场景保存来源章节、忠实度、是否包含新增内容和原文证据；合并、压缩、重排或合理扩写记录在 `adaptationNotes` 中。作者可以判断每个场景来自哪里、AI 做了什么改动，而不是只得到无法核对的剧本正文。

### 7. 支持多服务商与模型型号切换

页面可配置 DeepSeek、智谱 GLM、通义千问、Moonshot/Kimi、OpenAI、Ollama 和其他兼容接口。同一服务商内可以切换多个模型型号，也可以填写自定义模型 ID，并在保存前独立测试连接。

### 8. 从生成结果扩展为作者编辑闭环

结构编辑器按人物、地点、道具和场景分类。作者可以新增、修改和删除故事资产，逐场调整动作与对白；删除资产时系统会清理相关引用。应用修改后，Java 会重新编号、校验并导出 YAML，使 AI 初稿能够继续打磨并形成稳定交付物。

## 原创实现

以上改进均由本项目独立实现，包括 Java 后端、异步生成任务、AI 接口适配、响应归一化、YAML Schema、跨引用校验、渐进式预览和浏览器结构编辑器。项目未复制 LumenX Studio 源码。
